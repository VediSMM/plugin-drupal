# Руководство VediSMM для Drupal

VediSMM для Drupal добавляет защищённый permission workflow для отправки материалов Drupal 11 в VediSMM.

Модуль хранит токен VediSMM в State API, а не в экспортируемой конфигурации. Действие по умолчанию создаёт черновик VediSMM; публикация запускается только явным действием и защищена permission и CSRF.

Администратор задаёт URL API и токен в разделе **Конфигурация → Веб-службы →
VediSMM**. Сохранённый токен никогда не выводится обратно в форму: пустое поле
пароля сохраняет прежний токен, а отдельный флажок явно удаляет его. Пока токен
не задан, запросы безопасно отклоняются.

## Трекинговые ссылки

Форма отправки использует нативные флажки Drupal Form API **Сокращать ссылки**
и **Добавлять источник площадки**. По умолчанию оба выключены. Form API
блокирует источник, пока сокращение выключено, а серверный mapping всегда
принудительно выключает источник в этом состоянии. CSRF обрабатывает нативный
Drupal Form API. Значения передаются только внутри `options.tracking`; модуль не
переписывает URL материала и не хранит состояние созданных ссылок.

ВедиSMM создаёт отдельную короткую ссылку для каждой целевой площадки. При
включённом источнике, если непустой `utm_source` отсутствует, ВедиSMM добавляет
`utm_source=<network>` и сохраняет существующий `utm_term`. Если `utm_source`
уже есть, ВедиSMM сохраняет его, а все существующие `utm_term` заменяет (или
добавляет один) ровно одним `utm_term=<network>`. Остальные query-параметры,
encoded values, их порядок и fragment остаются без изменений.
